# セキュリティの12項目（アプリを作るときの条件）

2026-11-10 ユーザーの指示：**自作するアプリは、次の12項目を作成の条件にする**。1〜4は欠けると即座に情報漏洩につながるので公開前に必須。
5〜8は、個人情報や AI を扱うなら同じく公開前に入れる。9〜12も公開前に用意する（間に合わないものは理由と残作業を書く）。

| # | 項目 | 条件 |
|---|---|---|
| 1 | ログイン認証 | パスワードを自前で保存しない（実績のある認証サービスを使う）。管理者は多要素認証を必須にする |
| 2 | 権限チェック | 「この人はこのデータを見てよいか」をサーバー側（DB の規則・API）で毎回確かめる。画面で隠すだけにしない。URL・ID を書き換えても他人のデータが取れないことをテストする |
| 3 | 秘密情報の管理 | API キー・DB のパスワードはサーバーの環境変数に置く。コード・ブラウザ・GitHub に置かない |
| 4 | 入力値の検査 | 利用者の入力はすべて疑い、形式と長さを検査する（SQL インジェクション・XSS を防ぐ） |
| 5 | 個人情報の最小化 | 必要な情報だけを集め、保存時は暗号化し、不要になったら削除する。外部の AI に送る前に氏名などを伏せる |
| 6 | 通信の暗号化 | すべて HTTPS |
| 7 | AI 機能の防御 | 読み込んだ文書に仕込まれた命令（プロンプトインジェクション）に備える。AI の権限を絞り、AI の出力をそのまま実行・表示しない |
| 8 | 回数制限 | ログイン試行・API の呼び出しに上限（総当たり・AI の高額請求を防ぐ） |
| 9 | ログと通知 | ログイン・権限変更・データの書き出しを記録し、異常時に通知する。ログに個人情報を書かない |
| 10 | ライブラリの更新 | 部品の脆弱性を自動で検査し（npm audit・Dependabot）、更新を続ける |
| 11 | バックアップと復元 | 自動で取得し、実際に戻せるかを試す |
| 12 | エラー表示の制御 | 利用者には簡潔な文言だけを見せ、内部の詳細はログに残す |

### 11 の復元の練習（ユーザー作業・年に1回以上）
1. Supabase → saiten-verify → Database → Backups で、最新のバックアップがあることを確かめる（Free プランには自動バックアップが無い）
2. 新しい空のプロジェクトを作り、バックアップから復元する（または `pg_dump` → `psql` で流し込む）
3. 復元した DB にアプリ（Preview）をつなぎ、ログイン・答案の一覧・返却が見えることを確かめる。終わったら空のプロジェクトを消す
