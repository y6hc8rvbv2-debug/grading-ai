# チャッピー先生：本物の OpenAI で確かめる手順（本人のキーを安全に使う）

> **いまの方針では使わない（2026-10-07）。** 生徒の復習は「本人の ChatGPT で復習」（B方式。`docs/REVIEW-CHATGPT.md`）だけを使う。
> この文書は、アプリ内の会話（A方式）を使うと決めた場合（環境変数 `TUTOR_INAPP=on`）のためのもの。B方式には、ここの設定（見回り・暗号鍵・`CRON_SECRET`・OpenAI の API キー）は要らない。

自動テストは OpenAI の代役で行っている。本物の OpenAI Realtime で動くか（通話の作成・イベント名・切断・料金）は、
**キーの持ち主（検証用に契約した人）が自分の PC と検証環境で**、次の順に確かめる（`docs/DB-RUNBOOK.md` 第1部の 1-6）。

> - **課金される確認（手順 C・D・E）は、依頼者が「実行してよい」と指示するまで行わない。**
> - 手順 B（モデル一覧）は生成を伴わないが、**料金がかからないことは公式の料金表でまだ確認できていない**（開発環境から料金表を開けない）。
>   実行する前に、OpenAI の料金表（https://openai.com/api/pricing/ など）でモデル一覧の取得に料金が書かれていないことを確かめ、実行後に Usage を見る
> - キーをチャット・メール・メモ・スクリーンショット・このリポジトリに書かない。管理者・学校のキーは使わない

## 呼ぶ API の一覧（`scripts/tutor-live-check/run.ts`）

| 手順 | 呼ぶ API | 生成（トークン） | 課金 |
|---|---|---|---|
| B. モデル一覧の確認（既定） | `GET https://api.openai.com/v1/models` を1回 | なし | 料金表に記載が無いことを依頼者が確かめる（開発側は未確認） |
| C. 通話の確認（`--paid`） | 上の1回に加えて `POST /v1/realtime/calls` を1回、データチャネルで `conversation.item.create`・`response.create` を1回ずつ、`POST /v1/realtime/calls/{id}/hangup` を1回 | 文字で1往復 | **課金される**（Realtime の利用） |

- これ以外の API は呼ばない。既定の手順が `GET /v1/models` の1回だけを呼ぶこと、確認の文を打たなければ何も呼ばないこと、
  環境変数のキーを使わないことは、代役のサーバーに対して単体テストで確かめている（`tests/unit/tutor-live-check.test.ts`）

## A. 準備（OpenAI の管理画面で。アプリの外）

1. 検証専用の **Project** を作る（例：`chappy-verify`）。普段使いのプロジェクトのキーは使わない
2. その Project に**予算の上限**（例：月 $5）と通知を設定する
3. その Project で **API キーを1つ作る**。権限を絞れる場合は、Realtime と Models の読み取りだけにする
4. キーはパスワード管理ソフトに保存する

## B. モデル一覧の確認（キーが有効か・音声会話に使えるモデル）

```bash
npm ci
npm run tutor:live-check
```

1. 呼ぶ API が表示される。よければ「モデル一覧を取得します」と入力する（それ以外なら何も呼ばずに終わる）
2. 「OpenAI API キー」と聞かれたら貼り付けて Enter（**入力した文字は表示されない**。パスワード管理ソフトのコマンドから渡してもよい：例 `op read ... | npm run tutor:live-check`）
3. 結果：キーが有効か、**音声会話に使えるモデル**（アプリの設定画面に出るものと同じ）、字幕に使う文字起こしのモデル
4. OpenAI の管理画面の Usage に、このときの料金が出ていないか確かめる

## C. 通話の確認（通話を1回・文字で1往復・サーバー側から切る）　※指示があるまで実行しない

```bash
npx playwright install chromium   # 初回だけ（Chromium で本物の WebRTC の申し込みを作る）
npm run tutor:live-check -- --paid
```

- 呼ぶ API（課金されるもの）が表示される。B と同じ確認のあと、さらに「有料で実行します」と**そのまま入力したときだけ**通話を作る
- 行うこと：本物の WebRTC の申し込み → アプリと同じ関数で `POST /v1/realtime/calls` → データチャネルで「1+1は？」→
  受け取ったイベント名をアプリが使う名前と照合 → `POST /v1/realtime/calls/{id}/hangup` → **ブラウザ側の接続が閉じたか**（＝サーバーから切ったら本当に切れるか）
- マイク・音声は使わない（文字だけ）。最大60秒。モデルは gpt-realtime-mini があればそれを使う
- すべて ✓ なら、接続方法・イベント名・サーバーからの切断が本物でも動く。✗ があれば、表示された内容を開発担当に渡す（キーは渡さない）

## D. 検証環境のアプリ（Vercel の Preview）での確認　※指示があるまで実行しない

前提：`docs/DB-RUNBOOK.md` 第1部の 1-1〜1-5 が終わっている（検証用の Supabase・Preview の環境変数・見回り）。

1. 管理者で設定画面 →「チャッピー先生」：見回りが「動いています」と出ている。学校とクラスで有効にする（1回の上限は最小の1分にしておくと確認が早い）
2. 先生で、練習用の答案を確認・返却する（検証用の生徒アカウントへ）
3. 生徒アカウントで `/student` → 受信箱 → 間違えた問題 → 設定で同意 → 手順 A のキーを登録（「保存しない」を推奨）
4. 「文字で質問する」→ 1往復 →「会話を終える」→ OpenAI の Usage に記録が出る
5. 終了の確認（それぞれ新しい会話で）
   - 1回の上限（1分）で止まる
   - 管理者が学校の設定で無効にすると、約40秒以内に止まる
   - 同意の撤回で止まる
   - **ブラウザのタブを強制終了**（タスクマネージャー等）すると、約2分10秒以内に、管理者の設定画面で「通話を切る処理の待ち」が0件に戻る
6. それぞれのあと、OpenAI の Usage で、切った時刻以降に料金が増えていないか確かめる（hangup で本当に止まったかの確認）

## F. 後片付け

1. OpenAI の管理画面で、手順 A のキーを**無効にする（削除）**
2. アプリに保存した場合は、生徒の設定画面の「保存したキーを削除」
