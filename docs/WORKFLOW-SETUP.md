# 時短採点・一斉返却（Previewで確認してから利用）

ベース: PR #1 / 18720d1。実データへのSQL実行、実AI呼び出し、実際の生徒への配信はしていません。

## 追加した操作

1. テスト管理の自動入力で「模範解答がない」を選び、問題文・図のある答案または問題用紙を追加します。
   生徒の手書きを正答の根拠にせず、印刷された問題からAIが解答案を生成します。問題文不足は教師が補います。
   印刷配点は維持します。全問に配点の記載がないときのみ100点を小問数で均等配分し、端数は先の設問から1点ずつ加算します。
   一部のみ配点がある場合、判読不能の場合、100問超の場合は自動配分しません。教師が確認・修正して登録します。
2. 新規採点に写真を追加すると、端末内で解像度・暗さ・低コントラストを検査し、同一ファイルを検出します。
   「問題番号・受験番号から自動振り分け」はHaikuを使います。受験番号・出席番号を名簿と照合し、問題番号とページ番号から後続ページの候補を作ります。
   候補・不足・重複を確認し、必要なら前へ／後へで並べ替え、生徒の割当を修正して確認チェックを付けます。
3. 新しい「全員確認・返却」画面（/batch-review）でテスト・クラス・設問を選びます。
   同じ問題を生徒別に並べ、原本の該当箇所・ページ全体・模範解答と採点条件を比較できます。
   全設問を確認後に生徒ごとに「確認した」を押します。点数・コメントを変えると再確認が必要になります。
4. 採点を走らせたタブを開いたまま、別タブで確認できます。確認画面は10秒ごとに更新します。
5. 全員分の本人対応と結果を確認し、一斉配信を押します。未提出・未採点・未確認・配信先未登録の場合はDBで拒否します。
   配信した時点の結果を保存するので、その後の教師の編集は再配信するまで生徒には反映されません。

## 配信先の初期設定（クラスごとに初回）

- 0001〜0009適用済みの検証用Supabaseで **0010_workflow.sql** を1回実行してください。
- 0010は3表、RLS、配信関数、得点編集後の確認解除トリガーを追加します。既存行の一括更新・削除はしません。
- Supabase Authで生徒の登録・メール確認を利用できることと、対象Previewの `/auth/callback` が許可済みredirect URLであることを確認してください。
- 生徒は同じアプリURLの `/student` で登録し、メール確認後にログインします。
- 管理者が「全員確認・返却」の「配信先を登録する」で名簿と本人のメールアドレスを照合します。教職員アカウントは配信先にできません。
- 生徒は本人の返却結果と画像だけを閲覧できます。氏名・メールを画像認識モデルへ送る必要はありません（写真自体に氏名が写っている場合はAPIへ送られます）。
- 一斉配信は本人専用ページへの公開です。ページが開いていれば30秒ごとに更新します。メール通知・OSのプッシュ通知は含みません。

## 節約する処理

3モデル併用では、前モデルの画質判定が良好な場合に限り、不確かな設問だけを上位モデルで再採点し、正常な設問は保持します。
問題文・図の共通条件を欠かさないよう、画像は全ページを渡します。画質不良・前段階で結果が得られない場合は全問を再採点します。
そのため入力画像の費用は削減しません。実際の費用と精度は実答案で別途検証が必要です。

## 限界と検証

- 自動振り分けはJPEG/PNG・1画像4MBまで。PDFは既存の手動割当で取り込めます。HEICは既存変換後の画像で扱います。
- 氏名による名簿照合は行いません。既存名簿には実名を保存しない設計のため、番号と教師確認を使います。
- 画質チェックは補助です。見切れ・薄い作図線などの完全な検出は保証しません。
- 返却先の本人確認、配信後の画像表示、実機操作、AI読み取り精度、継続中の採点と教師確認の通し操作はPreviewで確認してください。
- 動いている採点タブを閉じると残りの採点は止まります。サーバー常駐のバックグラウンドキューは追加していません。
- 本番へのマージ、Supabaseへの適用、実API試験は未実施です。

## 個別返却（0011）

0001〜0010適用済みのDBに `supabase/migrations/0011_individual_return.sql` を実行します。
関数1つを追加するだけで、SQLの実行自体では成績の変更や返却は行いません。再実行可能です。
Previewの「全員確認・返却」で対象の答案カード上部の「この生徒に返却」を押し、対象と点数を確認します。
配信先登録・全設問の採点と教師確認が必須です。ほかの生徒の未提出は個別返却を妨げません。

同じ内容を再度返却しても複製されません。成績を編集すると再確認が必要で、再返却までは前の返却内容が残ります。
一斉配信の全員確認条件は変更していません。

## 新規採点から開始する

1. 「新規採点」で答案を取り込む。1人分の全ページを同じ生徒へ割り当て、順序・不足を確認する。
2. 「3. 模範解答・配点を準備する」で、資料に使う1人を選び「この答案から新しいテストを作る」を押す。
3. 選んだ生徒の全ページが「生徒の答案」として引き継がれる。模範解答がない設定で始まり、印刷された問題から解答案を生成する。模範解答がある場合は追加して設定を切り替える。
4. AI読み取りを明示的に開始し、正答・配点と要確認の設問を確認。「登録して採点に戻る」で新しいテストが選択される。答案写真・割り当ては残る。
5. 「4. テストを確認して採点する」で正答・配点を開いて確認し、チェック後に採点する。

既存テストもここで明示的に選択できる。以前のテストを自動選択しない。テスト未登録でも答案の取り込みから開始できる（クラスの登録は必要）。作成途中の内容は専用の下書きに保存し、次回の作成時に復元するか選択できる。テスト管理の下書きとは別に保存する。追加SQLは不要。

今回の変更は操作経路と取り違え防止であり、AIの読み取り精度を改善したという意味ではない。本物の資料の正答・印刷された配点との照合は引き続き必要。
