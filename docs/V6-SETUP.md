# テスト採点ver6　先生（管理者）がする設定と、最低限の確認

ver6 は ver5 と同じサーバーをそのまま使います。**新しく契約するサーバーはありません。**
先生にしていただくのは、下の「必須」の2つだけです（どちらも画面の操作とコピー＆貼り付けだけ）。
「任意」は、その機能を使うときだけ行ってください。

---

## 使うサーバー（ver5 と同じ）

| 役割 | サービス | ver6 で増えた設定 |
|---|---|---|
| アプリを動かす | **Vercel** | なし（必要なら環境変数を1つ足す：下の 2.） |
| データ・ログイン・答案の画像 | **Supabase**（東京） | SQL を1つ実行する（下の 1.） |
| 採点AI | **Anthropic（Claude）** | なし（AI は設定画面から切り替え） |
| 月額・前払いの支払い | **Stripe**（任意） | 支払い方法をオンにする（下の 3.） |
| 暗号資産の支払い | **NOWPayments か Coinbase Commerce**（任意） | アカウントとキー（下の 4.） |

> Stripe の暗号資産・ステーブルコイン決済は、2026年10月の時点で日本の事業者は使えません（米国の事業者だけ）。
> そのため、暗号資産は専門の決済代行につなぐ形にしています。

---

## 必須 1．Supabase で SQL を実行する（約5分）

1. Supabase にログインし、プロジェクトを開きます
2. 左のメニューの **SQL Editor** を開きます
3. まだ実行していないファイルを、**番号の順に1つずつ**貼り付けて「Run」を押します
   - 本番に実行済みなのは 0001〜0003 だけです（2026-09-28 時点）。0004〜0018 も、まだなら番号の順に実行します（手順は `docs/DB-RUNBOOK.md`）
   - 最後に **`supabase/migrations/0019_ver6.sql`**（ver6 の追加分）を実行します
4. 「Success」と出れば完了です。エラーが出たら、その画面のまま開発担当に知らせてください（何も変わらずに止まります）

> まず検証用のプロジェクト（saiten-verify）で試し、問題がなければ本番で同じことをする順番がおすすめです。

## 必須 2．Vercel の環境変数を確かめる（約3分）

Vercel → プロジェクト → **Settings → Environment Variables** で、次の2つがあるか確かめます（ver5 で設定済みなら何もしません）。

| 名前 | 何に使う | 無いとき |
|---|---|---|
| `ANTHROPIC_API_KEY` | AI 採点・自動振り分け・模範解答づくり | AI を使えません |
| `SUPABASE_SERVICE_ROLE_KEY` | 生徒のタブレット・スマホからの提出（ver6）・アカウントの削除 | 生徒の端末から提出できません |

足したときは、**Deployments → 最新のもの → Redeploy** を押して反映します。

---

## 任意 3．支払い方法を増やす（Stripe・約5分）

コードの設定は不要です。Stripe のダッシュボードで、使いたい方法をオンにするだけです。

1. Stripe → **設定（歯車）→ 支払い方法**
2. 使いたいものをオンにします
   - 月額の自動更新：**カード・Apple Pay・Google Pay・Link**
   - 前払い（1・3・6・12か月分）：上に加えて **コンビニ払い・PayPay・銀行振込**
3. Stripe → **開発者 → Webhook** の送信先（`https://<アプリのURL>/api/billing/webhook`）に、次のイベントが入っているか確かめます
   - `checkout.session.completed`・`checkout.session.async_payment_succeeded`・`checkout.session.async_payment_failed`・`checkout.session.expired`（コンビニ払い・銀行振込の入金の知らせ）

## 任意 4．暗号資産（ビットコイン・ステーブルコイン）を受け付ける

どちらか一方を選びます（両方は使いません）。

**NOWPayments の場合**
1. NOWPayments のアカウントを作り、受け取る通貨の口座（ウォレット）を登録します
2. **API キー**と **IPN 秘密鍵**を作ります。IPN の送信先は `https://<アプリのURL>/api/billing/crypto/webhook`
3. Vercel の環境変数に `CRYPTO_PROVIDER=nowpayments`・`NOWPAYMENTS_API_KEY`・`NOWPAYMENTS_IPN_SECRET` を足して Redeploy

**Coinbase Commerce の場合**
1. Coinbase Commerce のアカウントを作ります
2. **API キー**と、Webhook（送信先 `https://<アプリのURL>/api/billing/crypto/webhook`）の **共有シークレット**を作ります
3. Vercel の環境変数に `CRYPTO_PROVIDER=coinbase`・`COINBASE_COMMERCE_API_KEY`・`COINBASE_COMMERCE_WEBHOOK_SECRET` を足して Redeploy

> 暗号資産は月額の自動更新ができないため、前払い（1・3・6・12か月分）として扱います。金額は円で決まり、相場の換算は決済代行が行います。
> 暗号資産で受け取った代金の会計・税務の扱いは、顧問の税理士にご確認ください。

## 任意 5．答案の写真の暗号化（AWS KMS・約20分）

答案の写真を暗号化して保存します。暗号化の鍵は **AWS KMS（鍵金庫）** の中にあり、AWS の HSM（専用の機械）から外に出ません。
Supabase の DB・保存場所・バックアップが丸ごと漏れても、写真は暗号文だけで読めません。設定するまでは、以前と同じく暗号化せずに保存します。

1. **AWS のアカウント**を作り（無い場合）、右上のリージョンを **アジアパシフィック（東京）ap-northeast-1** にする
2. **KMS → カスタマー管理型のキー → キーの作成**
   - 種類：**対称**・用途：**暗号化および復号化**・別名：`test-saiten-answers`
   - **自動ローテーション（毎年）をオン**にする（古い鍵も残るので、以前の写真も読めます）
   - 作成したキーの **ARN**（`arn:aws:kms:ap-northeast-1:…:key/…`）をメモ
3. **IAM → ユーザーの作成**（名前：`test-saiten-kms`。画面へのログインは不要）→ 許可の設定で **インラインポリシー** を作り、次だけを許可する
   ```json
   { "Version": "2012-10-17", "Statement": [{ "Effect": "Allow", "Action": ["kms:GenerateDataKey", "kms:Decrypt"], "Resource": "（手順2の ARN）" }] }
   ```
   そのユーザーの **アクセスキー** を作る（用途は「AWS の外で実行されるアプリケーション」）。キー ID とシークレットをコピー（チャットには貼らない）
4. Vercel → **Settings → Environment Variables**（Preview と Production の両方にチェック）に足して **Redeploy**
   | 名前 | 値 |
   |---|---|
   | `IMAGE_ENC_PROVIDER` | `aws-kms` |
   | `AWS_KMS_KEY_ID` | 手順2の ARN |
   | `AWS_REGION` | `ap-northeast-1` |
   | `AWS_ACCESS_KEY_ID`・`AWS_SECRET_ACCESS_KEY` | 手順3のキー |
5. 設定画面 →「AI採点の準備状況」の **答案の写真の暗号化** が ✓ になったら、**「答案の写真の暗号化」→ 以前の写真を暗号化する** を押す（管理者。何度押しても同じ結果）

> **大事：KMS のキーは削除しないでください。** 削除すると、暗号化した写真は二度と読めなくなります（AWS は削除の前に7〜30日の待ち期間を置きます）。
> 費用の目安は、キー1つで月1ドル程度＋使った回数（ごく少額）です。契約前に AWS の料金表でご確認ください。
> 採点のために写真を Anthropic に送ることは変わりません（送る直前にサーバーで復号します）。

## 任意 6．パスキー（指紋・顔認証）でのログイン（約5分）

パスワードの代わりに、端末の指紋・顔認証・画面ロックでログインできます。サーバーには公開鍵だけが残ります。

1. Supabase → **Authentication** の設定で **パスキー（Passkeys / WebAuthn）を有効**にする
   - 「Relying Party ID」には、アプリを開くドメインを入れる（本番は `saiten.school-app1.com`、検証用は Preview の固定 URL のドメイン）
   - 画面の項目名は、Supabase の更新で変わることがあります
2. Vercel の環境変数に `NEXT_PUBLIC_PASSKEY_ENABLED` = `1` を足して **Redeploy**
3. ログイン画面に「パスキーでログイン」、設定画面の「アカウント」（生徒は「アカウント」タブ）に「この端末をパスキーとして登録する」が出ます

## 氏名欄の塗りつぶし（設定は不要）

「新規採点」のおまかせモードで **「氏名欄を塗りつぶしてから保存する」** にチェックすると、AI が見つけた氏名欄を、保存する前に塗りつぶします（端末に記憶。既定はオフ）。
氏名欄が見つからない・位置が不自然な答案は、解答を消さないように塗りつぶさずに保存します（採点の記録に枚数が出ます）。生徒の端末からの提出は対象外です。

## 最低限の確認（先生にお願いすること・約15分）

開発側で、AI と決済の代役を使った自動テスト（合計 400 件以上）はすべて通っています（`docs/V6-VERIFICATION.md`）。
本物の AI・本物の端末でしか確かめられない、次の5つだけをお願いします。

1. **設定画面 →「AI採点の準備状況」** がすべて ✓ になっている（0019 と環境変数の確認）
2. **新規採点**：実際の答案を5枚ほど入れる → 自動で生徒・テストが選ばれ、5秒後に採点が始まり、数十秒で終わる
3. **生徒のスマホ**：新規採点 →「生徒のタブレット・スマホから」→ QR コードを自分のスマホで読み、1枚撮って提出 → 先生の画面に届いて採点される
4. **模範解答がないテスト**：問題用紙の写真から「模範解答がない」で作る → 「検算一致」の印が付いた設問の答えが正しいか、数問だけ見る
5. **設定画面 →「AIエンジン」**：Haiku 5.5・Sonnet 5.5・Opus 5.5 が表示されている

うまくいかないときは、画面に出た文言をそのまま開発担当に知らせてください。
